# go-unstructured

Unofficial Go clients for the Unstructured Platform and Partition APIs, generated from Unstructured's public OpenAPI documents. For using the clients from an agent, read [.agents/skills/go-unstructured/SKILL.md](.agents/skills/go-unstructured/SKILL.md). This file covers changing the code.

## Architecture

Two generated packages, driven by their own `gen.go` files:

- Root package `unstructured`: `scripts/fetch-spec.sh` downloads `https://platform.unstructuredapp.io/openapi.json` to `api/openapi.json`; `scripts/fix-spec.sh` applies `scripts/patch-spec.jq` to write `api/openapi.fixed.json`; `go tool oapi-codegen` uses `config.yaml` to write `client.gen.go`.
- Subpackage `partition`: the same scripts download `https://api.unstructuredapp.io/general/openapi.json` to `api/partition.json`, write `api/partition.fixed.json`, and generate `partition/client.gen.go` with `partition/config.yaml`.

Both pipelines generate the whole spec. The downloaded and patched specs stay gitignored.

## Stack

- Go 1.26.9.
- oapi-codegen v2.8.0, pinned as a `tool` dependency in `go.mod`.
- Runtime: `github.com/oapi-codegen/runtime`.

## Layout

- `gen.go`, `config.yaml`, `client.gen.go`: Platform client.
- `partition/`: Partition client, config, generation directives and tests.
- `client_test.go`, `example_test.go`: Platform tests and the README example.
- `scripts/`: spec download and patch, lint and security scans.
- `api/`: downloaded specs, gitignored.
- `vendor/`: committed dependencies, regenerated by `make dep`.

## Dev workflow

Everything runs in the `Dockerfile.dev` image. You need Docker and Make.

```bash
make dep       # go mod tidy + go mod vendor
make generate  # download the spec and regenerate
make lint      # shellcheck, shfmt, go fix, golangci-lint
make test      # go test -race
make sec       # gitleaks, govulncheck, semgrep
```

## Project-specific landmines

- Both specs use OpenAPI 3.1 nullable unions and schema keywords that need downconversion before generation. `scripts/patch-spec.jq` rewrites nullable `anyOf` branches, collapses singleton unions, converts `const` to `enum` and schema `examples` to `example`, then sets OpenAPI 3.0.3.
- UUID-or-string unions accept any string. The patch flattens them to `string`, preserving accepted values and preventing path and query parameters from becoming anonymous union structs with inaccessible storage.
- Both configs map `number` to `float64`; keep the mapping in both packages.
- Open-ended additional properties and unspecified JSON response bodies use `json.RawMessage` through a spec extension. Keep their JSON bytes intact; decoding them into `interface{}` loses large integer precision and triggers the security scan.
- Both APIs send the key in `unstructured-api-key`. The Platform spec declares it as an optional header parameter rather than a security scheme. The Partition spec declares `ApiKeyAuth` and an anonymous alternative. The generated clients do not install authentication automatically.
- Partition accepts multipart uploads. Use its raw body method with a multipart writer and the writer's content type when sending a file.
- Method names come from operation IDs. Several notification methods include the full route in their names.
- `make generate` fetches the latest specs. Review generated changes even when local config did not change. Never edit generated files by hand.
- Work only inside this workspace. No Git or GitHub mutations, publication or calls to live API operations are authorized for this task.
- `.github/workflows/regen.yml` regenerates the client every day and releases the result. When the checks fail, Claude edits the repository to fix them, but a fix may not touch the paths listed under `fix_protected_paths` in that workflow: the workflows, the Makefile, `AGENTS.md`, `.agents/rules/`, the lint, security and spec download scripts and their configs. A problem that needs a change there fails the run and needs a manual fix.
